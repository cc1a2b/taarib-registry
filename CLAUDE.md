## Stack

Data-only repo: static JSON catalogue Taarib reads, plus a hand-curated index. No build.
`fahras/jadwal.py` (stdlib only) regenerates the README tables from the index.

## Domain and layout

- Public catalogue the Taarib client resolves over raw.githubusercontent.com / CDN / local copy
- sharaih/ (256 shards), isdar/ (releases), sahb/, bayan.json — generated, read by the client
- fahras/ — tarjamat.json (community Arabic translations of PC games: links and the facts each
  page states, nothing hosted), mukhattat.json (its JSON Schema), jadwal.py — hand-curated,
  not read by the client, so it never moves the manifest sequence

## Architecture facts Claude cannot infer

- The catalogue tree (sharaih/, isdar/, sahb/, bayan.json) is generated by taarib-mustawda's
  sabk.rs in the Taarib repo; do not hand-edit it, regenerate from the client and commit the output
- fahras/ is the one part written by hand; every entry must cite the URL that was actually read
  (`tahaqquq.rabt`) and record only what that page states
- The publisher name belongs in binary version info only (set once in Taarib's tauri.conf.json
  and unity/Directory.Build.props), never in this repo's README, LICENSE, data or GitHub description

## Gotchas

- Editing catalogue JSON by hand will diverge from the generator — change the generator instead
- After editing fahras/tarjamat.json, validate against mukhattat.json and rerun jadwal.py so
  both READMEs match the data
